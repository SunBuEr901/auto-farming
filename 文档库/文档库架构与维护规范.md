# 文档库架构与维护规范

版本：v2.1 验收修订｜更新：2026-10-12｜适用：本项目文档与 agent 交接。

目标：人快速看懂状态并照着操作，agent 按需找到实现和证据。**一个事实一处维护，摘要链接原文；只记录能帮助下一次工作的内容。**

## 1. 四类核心文档

| 类别 | 回答什么 | 本项目主维护位置 |
|---|---|---|
| 状态 | 能做什么、卡在哪里、接下来做什么 | [当前状态](当前状态.md) |
| 架构 | 模块如何连接、代码与接口在哪里 | [架构与代码地图](架构与代码地图.md) |
| 操作 | 怎样启动、检查、停止与恢复 | [基本使用说明](../小车基本文档与使用说明.md)、[机械臂专题](机械臂ROS1与MoveIt入门.md) |
| 记录 | 改了什么、依据是什么、还有什么没验证 | [发现与变更记录](发现与变更记录.md)，引用测试报告或附件 |

[首页](README.md)按任务导航，不再重复全文件清单；课程明细放在专题，根 README 只保留项目和阶段摘要。规范与[模板](文档模板.md)是辅助工具，不增加业务文档层次。沿用现有文件名，不建立平行的英文目录体系。

故障、接口、测试和方案决策先写入相关文档或记录。只有内容需要反复引用、独立验证或明显妨碍阅读时才拆专题；拆分后旧入口保留链接，索引同步。不要预建空目录、为每次工作新建报告或重复复制配置。

## 2. 事实与证据

- 重要结论写明**来源、日期、适用设备或版本、验证范围**。优先使用匹配当前环境的实测；用户确认、项目记录和厂商资料保留各自来源，不能一律标为实测。
- 无把握就写“待确认”或“推测”。IP、参数、接口、型号、版本、标定值不得凭惯例补全。资料支持的预期写为待验证，不冒充本机状态。
- 文档更新日期与设备验证日期分开。复用旧内容时将“本次／当前”改为明确日期，历史原因不能直接诊断当前故障。环境改变后标记受影响结果“待复核”。冲突先核对对象、版本和时间，不能只看文件更新时间。
- 验收统一用“未测试／部分通过／通过／未通过”，必要时另写“暂缓”等工作安排。软件启动、仿真、真机通信、运动与停止分别验收。
- 排查过程和失败尝试留在记录；操作正文保留有效步骤，必要的失败判断可以引用。推翻旧结论时加取代说明和链接，保留原始证据。
- 不保存密码、令牌或 X11 cookie。凭据只记录用途、获取或恢复方式；原始日志先脱敏。临时日志未归档就如实注明；大型数据只记录可定位位置及必要校验信息。

## 3. 写得短，也能执行

专题头部只需“更新日期＋适用环境”；涉及设备结果再写“最后验证日期＋来源”。无需每篇强制填写负责人、文档 ID、信任等级和生命周期；已有编号可继续使用。

操作保留：**前提 → 执行位置与命令 → 预期及验证 → 停止／回退**。去重仍要保留就地判断所需的上下文和有出处的参考值。必须分清 Windows、Jetson 和容器。对运动、固件或持久配置操作补充实际影响与恢复条件；恢复方法未知就标注，不编造。未执行命令明确标为待验证。

架构保留模块职责、依赖、源码与部署位置、验证入口。涉及接口时补类型、单位、坐标系、时序与异常／停止语义，只写任务所需字段。区分本地修改、设备部署和测试；实际源码与版本需要核对，文档不能代替源码。

记录使用[简短模板](文档模板.md)：日期、证据、操作、结果、未验证项；必要时补备份和结束状态。复杂测试才另存报告，不要求一份事实同时填满多张表。

## 4. Agent 使用与维护

先读项目约定、索引和状态；操作任务读对应手册，编程任务再读架构、相关接口与真实源码。只查任务相关的历史记录和 PDF。执行指引见 [robot-doc-governance skill](../skills/robot-doc-governance/SKILL.md)。

完成工作后，按影响更新：

| 本次发生什么 | 更新哪里 |
|---|---|
| 仅查询、解释或润色，没有新工程事实 | 通常不新增工程记录；只改用户要求的内容 |
| 新发现、配置／代码变更或测试结果 | 主维护文档＋一条变更记录；能力或阻塞改变才更新状态 |
| 操作方式改变 | 同步使用说明或对应专题；使用说明保留可找到的新入口 |
| 新专题或重要阶段结论 | 分别更新索引或根 README |

收尾检查除链接与证据外，还按受影响任务走读入口、步骤、成功判断和停止；不以链接数量代替可用性。文档整理成果留在变更记录，不占设备能力或待办表。交接只说变化、验证与未完成项，不为“保持一致”触碰无关文件，不自动部署、发运动指令、提交或推送。

## 5. 两版设计的取舍

参考用户提供的 [robot-doc-governance-skill.zip](https://github.com/SunBuEr901/auto-farming/blob/main/robot-doc-governance-skill.zip)，结合本项目已有设计：

- 保留原 skill 的证据约束、正式结论与实验过程分离、历史可追溯，以及只更新相关文档；保留本项目的状态入口、代码地图和分层验收。
- 将八套模板、六级信任标签和多目录规划压缩为四类核心文档与一页可选模板。取消强制文档编号和多套元信息。
- 不沿用未指定型号的模型白名单；模型选择遵循用户或项目的明确要求，质量依据证据与验证判断，skill 不自行切换模型。
- 不沿用允许明文凭据的规则，执行本项目不保存秘密信息的约定。

本版取代 2026-10-12 初版中较重的目录、元信息和模板要求；历史设备结论与证据保持原有适用边界。

# 文档模板

更新：2026-10-12。按需取用，删除无用栏目；未知值写“待确认”，不要默认填“通过”。日期＋标题通常足够，已有记录编号可沿用。

## 操作

```text
# 任务名称
更新：日期｜适用：设备／环境｜最后验证：日期与证据，或未测试
目标与前提：必要条件及会影响的设备
步骤：执行位置、环境加载、命令、预期结果和失败出口
结束：停止与检查；持久变更的备份和回退
边界：尚未验证的部分及相关文档链接
```

## 状态与架构

状态行：`能力 | 结果及范围 | 最后验证日期 | 证据与限制`；接着列真正影响下一步的阻塞和待办。

模块段落：职责与依赖 → 源码／符号与版本 → 部署位置 → 必要接口 → 验证入口。接口按任务需要记录类型、单位、坐标系、时序及异常／停止语义。

## 变更与交接模板

```text
## 日期：主题
- 证据：来源与环境；注明本次实测、历史记录或用户确认。
- 操作：改了什么、为何修改；必要时列部署与备份。
- 结果：实际观察、验收范围；必要时补设备／进程结束状态。
- 未验证：还缺什么、下一步如何确认。
- 相关文档：链接到主维护位置；证据复杂时链接独立报告。
```

独立测试按需补：预先约定的标准、版本、执行步骤、观测时长／样本、附件和结束状态。故障补根因是否确认、排除证据及回归；重要决策补备选、理由与代价。无需为它们各建一套必填模板。

# 机器人文档维护与利用

以项目 `AGENTS.md` 为入口，按已有目录定位，不为套用 skill 重建结构。本项目集中正文在 `docs/`，模块同级副本在 `modules/`；其他项目按实际路径使用。

## 按任务读

- 模块任务：直接读对应目录的 `AGENTS.md`、短 README 和需要的专题。同级副本带来源与校验值；无需重复读取集中版，不默认扫描全盘或通读 PDF。
- 全局状态或跨模块任务：读 `docs/README.md`，按需取状态、待验证清单和架构。状态查询区分最近已知能力与实时运行情况。
- 操作：核对执行环境、前提、验证和停止方法。编程／排障再读真实源码、接口和部署边界；文档中的远端路径不表示本地已有代码。
- 资料缺失时定向搜索；只展开相关历史证据。不能从命名惯例补全接口，也不为了查文档自动连接设备。

## 证据边界

重要事实保留来源、日期和适用环境。区分当前读回、历史实测、用户确认、厂商示例、设计设想与推测；未知写 TODO / 待验证。不能编造型号、IP、版本、参数、状态或测试结果。

文档更新不是设备复测；历史通过不是实时在线。环境变化后标明待复核；新证据推翻旧结论时保留原记录并注明取代关系。冲突先核对对象、版本和时间，不仅按更新时间判断。

USB 枚举、协议应答、ROS master、图形窗口、模型加载、仿真、真机运动与停止分别验收，使用“未测试／部分通过／通过／未通过”并限定范围。不保存密码、令牌或 X11 cookie，日志先脱敏。

## 维护与同步

1. 找到受影响事实的集中维护源；生成副本只供阅读，先比较漂移内容再覆盖。只更新受影响文档，不机械触碰所有入口。
2. 新环境、根因、配置、命令或测试结果追加简短记录：日期、证据、操作、结果、未验证项。能力变化更新状态，操作变化更新指南，新专题更新导航，重要阶段更新根 README。查询或润色没有新事实时不制造工程记录。
3. 本项目使用 `python tools/docs/doc_tools.py sync` 同步同级副本，`python tools/docs/doc_tools.py check` 检查路径、锚点与漂移。新增副本在 `docs/agent-mirrors.json` 映射；其他项目使用已有同步机制，不手工维护两套正文。
4. 修改 skill 以项目源码为准，运行 `python tools/docs/doc_tools.py pack` 更新分发包；安装副本同步核对，未同步则明确版本差异，不另立维护源。

操作正文写清前提、执行位置与命令、预期及失败判断、停止／恢复；分清 Windows、宿主机与容器。未执行步骤标为待验证，恢复方法未知不编造。架构按需要写职责、依赖、源码版本、部署、接口单位／坐标／时序与验证入口。

## 收尾

检查受影响链接、来源、日期、未知项和取代关系，走读入口到操作、验证、停止；链接通过不能替代内容审阅或设备测试。交接简述变化、验证与未完成项，区分文档更新、本地修改、部署和复测。

用具体、平实的文字说明约定，不叠加强调口号或无关流程。文档流程不扩大授权，不自动控制设备、部署、提交或推送；不指定或自行切换模型。

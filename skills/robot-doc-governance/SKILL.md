# 机器人文档维护与利用

让人能照着操作，让 agent 能找到实现；只沉淀下一次工作需要的信息。适应项目已有路径，不为套用此 skill 重建目录。

## 先找，再读

读取适用的 `AGENTS.md`，找到文档索引与状态页。无人农场项目默认入口是 `文档库/README.md`、`文档库/当前状态.md`；其他项目按实际文件映射。

- 查询状态：读状态和相关证据，区分最后已知能力与实时运行情况。
- 执行或解释操作：读对应手册，确认环境、前提、验证与停止方法。
- 编程或排障：再读架构／代码地图、相关接口和真实源码，核对源码版本与设备部署。文档未提供的接口不能靠惯例补全。
- 维护结构：先找主维护位置和现有引用；保留有效内容与历史证据，消除重复。入口按任务导航，不重复建立全文件清单；课程等明细放在相关专题。

只展开任务相关的记录、附件或 PDF。缺少入口时用文件搜索定位；信息不足不自动创建整套文档，也不为了回答查询默认连接设备或修改文件。

## 用证据判断

- 重要事实带来源、日期和适用范围。匹配当前环境的设备读回优先；历史实测、用户确认、配置文件和厂商资料保留各自来源。来源冲突先核对设备、版本和时间，未解决就明确冲突。
- 未知写“待确认”，假设写“推测”。不能虚构型号、IP、版本、ROS 接口、串口参数、尺寸、标定值或服务状态；厂商默认值不是本机实测。
- 文档更新不是设备复测；过去通过不是当前在线。复用旧内容时将“本次／当前”改为明确日期；历史原因不能直接作为当前故障的诊断。环境变化后将受影响结论标为待复核，保留旧测试。
- 验收写“未测试／部分通过／通过／未通过”，限定对象和条件。USB 枚举、协议应答、软件启动、仿真、真机运动与停止分别判断。

## 最小更新

四类信息各有主维护位置：**状态、架构、操作、记录**。索引只导航；摘要链接主文档，不复制整套参数或命令。去重时保留操作就地判断所需的最小上下文和有出处的参考值，不让读者为一次基本操作反复跳转。

1. 找出本次新增或被推翻的工程事实及证据。仅查询或润色且无新事实时，不制造工程记录。
2. 更新受影响的主文档，追加一条简短记录：**日期、证据、操作、结果、未验证项**；必要时加部署、备份与结束状态。复杂测试才另存报告。
3. 能力或阻塞变了才更新状态；操作变了同步使用说明或其专题入口；新专题更新索引，重要阶段更新根 README。文档整理成果留在变更记录，不加入设备能力或待办表。无需触碰其余文件。
4. 旧结论被推翻时加取代说明与新证据链接，保留原始记录。排查尝试留在记录，正式操作保留有效流程及必要的失败判断。

专题需要独立复用或验证时才拆分，不预建空目录。头部通常只需更新日期、适用环境；涉及设备结果再加验证日期与来源。沿用项目模板；没有模板时使用上述最小字段，不强制增加编号、负责人、信任标签或多套状态。

## 写到足够执行

操作写清：前提 → 执行位置与命令 → 预期及验证 → 停止／恢复。区分 Windows、设备宿主机和容器；未执行命令标为待验证。运动、刷写或持久配置步骤要有实际影响与恢复条件，未知方法不得编造。

架构写清职责、依赖、源码／符号与版本、部署位置、验证入口。接口按任务需要写类型、单位、坐标系、时序及异常／停止行为。区分本地修改、已部署和已验证；找不到源码或协议时记录缺口，并继续不依赖该缺口的工作。

不在文档、脚本或日志保存密码、令牌、X11 cookie；只留获取方式或存储引用。日志先脱敏，临时文件未归档要注明；大型数据用可定位引用及必要校验信息。

## 收尾

检查变更涉及的链接、来源、日期、未知项和取代关系，核对状态摘要与主文档。操作或结构调整后，按受影响任务走读“入口 → 步骤 → 成功判断 → 停止”，确认不缺关键上下文；链接通过不等于内容可用，无需为此执行设备命令。简短报告变化、验证与未完成项。

修改 skill 时以项目源码为准；已有安装副本或分发包需同步或明确标为旧版，不另建一套维护源。

文档流程不扩大任务授权，不自动部署、控制实物、提交或推送。不指定或自行切换模型；用户或项目另有明确要求时遵循，不能声称执行环境未提供的模型保证。

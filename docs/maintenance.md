# 文档维护规范

版本：v3｜更新：2026-10-17。此版取代旧规范中“保留全部原路径、不建立英文目录”和“每次先读索引与状态”的要求；证据与分层验收约定继续保留。

## 维护位置

| 内容 | 手工维护源 |
|---|---|
| 项目目的与导航 | 根 README、docs/README.md |
| 已有能力与阶段 | [status.md](status.md) |
| 未知项与关闭条件 | [pending.md](pending.md) |
| 硬件／软件环境 | environment/ 下对应专题 |
| 启动、验证、停止、回退 | guides/ 下对应指南 |
| 故障现象与诊断边界 | [排障](troubleshooting/README.md) |
| 源码职责、依赖、部署与接口 | [architecture.md](architecture.md)、modules/ 下模块正文 |
| 历史证据与时间线 | reports/ 与 [changes/README.md](changes/README.md) |
| 方案、原件及来源 | plans/、references/、assets/；课程二进制放对应模块 vendor/ |

集中版保留完整可读内容。模块目录的副本按 [agent-mirrors.json](agent-mirrors.json) 生成，保留来源、原文校验值和正文；链接自动改为副本位置适用的相对路径，同一模块内存在的副本优先互相链接。生成副本不接受手工修改，不成为另一套事实来源。

## 命名与阅读成本

- 文件和目录采用有含义的小写英文、数字与连字符，日期采用 `YYYY-MM-DD`。约定入口使用 `README.md`、`AGENTS.md`、`SKILL.md`；不另建 `AGENT.md` 平行规则。
- 中文用于标题、说明和任务导航。厂商原件重命名时记录原名与 SHA-256，保留文件字节，不为统一命名修改文中设备路径、ROS 包名或命令。
- Agent 从根约定直接选择模块，读取短入口及任务文档。只有跨模块、状态查询或证据核查时再读取全局正文和报告。不要把所有内容塞入自动加载的 AGENTS.md。
- 只为有内容的模块建立目录；没有源码就明示缺口。后续新源码归入对应模块，必要时继续按子模块细分并配置相关副本。
- 本次保留根旧使用说明和旧文档库 README 作为简短兼容入口，其余原路径用[迁移清单](reports/2026-10-17-file-inventory.json)追溯。旧报告中的字面路径仍表示当时位置。

## 事实与操作

重要事实写明来源、日期、设备／版本及验证范围。当前读回、历史实测、用户确认、厂商示例、推测和方案分别表达；不能将历史在线、默认值或设计目标写成当前状态。未知写 TODO / 待验证，解决冲突时保留旧证据并写明取代关系。

操作包含前提、执行位置、命令、预期、失败判断及停止／恢复；区分 Windows、设备宿主机、容器。未执行的命令标明待验证。运动、刷写或持久变更需有实际影响和恢复条件，未知方法不编造。

验收使用“未测试／部分通过／通过／未通过”，明确对象和条件；USB 枚举、协议应答、软件启动、仿真、真机运动与停止分别记录。模型存在不能替代模型加载成功。

不保存密码、令牌或 X11 cookie。证据日志先脱敏，大文件保留来源、日期和校验值。备份位置及恢复测试若尚未建立，就记录为待验证；Git 记录本身不是异地备份证明。

## 修改与验证

1. 修改受影响的集中正文，不改生成副本。若副本已漂移，先比较差异，保留有依据的内容再同步。
2. 新工程事实追加一条变更记录：日期、证据、操作、结果、未验证项；能力变化才更新状态，操作变化更新相应指南，新专题更新导航。纯查询或润色不制造工程记录。
3. 运行 `python tools/docs/doc_tools.py sync` 与 `python tools/docs/doc_tools.py check`。新增／移动正文时同步镜像映射及引用，收尾走读入口、步骤、成功判断和停止。链接通过不等于设备验证通过。
4. skill 修改以项目源码为准，执行 `python tools/docs/doc_tools.py pack` 同步分发包。已安装副本需同步核对；若受环境限制未同步，就在交接中明确旧版状态，不能宣称已升级。

[工具说明](tooling.md)列出检查范围。历史报告原则上只补来源、路径和取代说明，不重写实验结果；本次审查成果记录为文档变更，不占设备能力表。模板按需使用，不强制增加多套标签和冗余表格。
